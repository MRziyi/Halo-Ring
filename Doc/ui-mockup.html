R08 Ring Remote — UI

Three jobs, one app: (1) show the wearer's biometrics that the ring streams in the background, (2) configure the ring, (3) host the resident background service that powers everything. The on-device UI is designed for two pairs of AR glasses with low-resolution, see-through display. Both pairs render the same content (no stereo, no parallax). Everything below is at 1:1 scale — the screens are 480 × 480 px, matching what the wearer actually sees.

Principles

1
Black canvas. Lit pixels leak into the user's view of the world. Default to pixel-off; light only what carries information.
2
Transient by default. The HUD is not always-on. It flashes on event, then disappears. Persistent UI only while the wearer is actively in a settings screen.
3
One column, one focus. No multi-pane, no grids of more than 3 items. The wearer reads top-to-bottom, picks one thing.
4
Big text, generous space. 480 px wide, viewing distance equivalent to a 43" virtual screen — overshoot intentionally.
5
Sound + ring LED, not just visual. The wearer may be looking past the display. Click + green flash + LED blink cover every state change.
6
Same image to both eyes. Rokid's single projector drives both eyes; X3 Pro's binocular optics receive the same content. We never compose stereo.

7. In-app navigation

The whole UI is operable with the ring (or with the glasses' own temple touchpad). Inside our Activity, gestures are short-circuited to call Compose's focus manager directly — same speed-up as the agent injection but with zero process boundary.

The focus indicator (green left bar + 7% tint) makes it unambiguous which row the next TAP will activate. Every focusable row uses the same indicator — list rows, CTAs, tab strip.

8. Notes for implementation

  • Compose target. One Activity (in :app) with a Compose root. For RayNeo, the Activity extends Mercury SDK's BaseMirrorActivity so the same composition is mirrored to both eyes for free. For Rokid, plain Activity (the optic handles the doubling).
  • Theme. Define Colors and Typography from the §1 tokens. No MaterialTheme default — we want Material widgets to look like our system, not the other way round.
  • Focus. Default Android focus traversal works on both targets (Rokid temple → DPAD, RayNeo via Mercury FocusHolder). Apply a global focus indicator: 2 px left bar + 7 % accent tint, exactly as drawn here.
  • HUD. Implemented as a Compose composable hosted by an overlay WindowManager view in the foreground service (so it can appear above any app, not just ours). Auto-hides after 2 s via delay() + remove().
  • Brightness. Inherit system; never override. Wearers expect the glasses' anti-light- leakage mode to apply uniformly.
  • Pixel discipline. If a UI element fits in less ink, prefer that. Every illuminated pixel costs display power. Avoid filled icons; line icons at 1.5 px stroke.
