Halo Ring · 环意

UI mockup
Where the ring goes, the world moves. 「环之所至，意之所达」
by Zack 紫意 · package com.halo.ring

Three jobs, one app: (1) show the wearer's biometrics that the ring streams in the background, (2) configure the ring, (3) host the resident background service that powers everything. The on-device UI is designed for two pairs of AR glasses with low-resolution, see-through display. Both pairs render the same content (no stereo, no parallax). Everything below is at 1:1 scale — the screens are 480 × 480 px, matching what the wearer actually sees.

The Compose implementation matching this mockup lives in app-project/app/src/main/kotlin/com/halo/ring/ui/. Token names below (--halo-bg, --halo-accent, …) match HaloColors/HaloType in HaloRingTheme.kt and the brand-asset spec in Doc/brand/README.md.

Pure black background — least light-leak through the see-through optic and lowest pixel draw. Green matches the ring's LED so visual + tactile feedback share a single brand colour. halo_mint_bright is reserved for the icon's three blade-head accents only — it does not appear elsewhere in chrome. Mute is only for secondary text; if a divider would do, use one instead. Warn / Bad only fire on real events; never decorative.

Principles

1
Black canvas. Lit pixels leak into the user's view of the world. Default to pixel-off; light only what carries information.
2
Transient by default. The HUD is not always-on. It flashes on event, then disappears. Persistent UI only while the wearer is actively in a settings screen.
3
One column, one focus. No multi-pane, no grids of more than 3 items. The wearer reads top-to-bottom, picks one thing.
4
Big text, generous space. 16 sp floor; 480 px wide content at viewing distance equivalent to a 43" virtual screen. Overshoot intentionally.
5
Sound + ring LED, not just visual. The wearer may be looking past the display. Click + green flash + LED blink cover every state change.
6
Same image to both eyes. Rokid's single projector drives both eyes; X3 Pro's binocular optics receive the same content. We never compose stereo.
7
Focus-only, no pointer. Rokid has no touchscreen; X3 Pro's touch is the temple bar. Any pointerInput/detectTapGestures on the content is dead code — stay on Modifier.clickable + standard focus traversal.
8
One green, no exceptions. No per-profile colour theming. The mint-bright is reserved for the icon's three blade-heads — nowhere else.

4. The transient HUD overlay

Not always-on. Appears for ~2 s on connection / mode-switch / low-battery events, on QUADRUPLE_TAP, or — when the gesture-hint mode is on — for 800 ms after every recognised gesture. Top-right corner so it never blocks the centre of vision. Same widget on top of whatever the wearer is doing.

Audit-pass 2026-05-13s (binocular re-anchor). On X3 Pro (binocular 1280 × 480) a naïve CENTER_HORIZONTAL lands x ≈ 640 — between the eyes, only visible at the nose. Workaround: when DisplayAdapter.isBinocular = true, HudOverlay uses Gravity.END + an x-inset of ~160 px so the pill lands in the right-eye region. 8. Notes for implementation

  • Compose target. One Activity (in :app) with a Compose root (HaloRingApp). For RayNeo, the Activity extends Mercury SDK's BaseMirrorActivity so the same composition is mirrored to both eyes for free; TempleFocusBridge wires temple-bar TempleAction events to Compose's focus manager. For Rokid, plain ComponentActivity (the optic handles the doubling; DPAD-key traversal works natively).
  • Theme. HaloColors and HaloType in HaloRingTheme.kt. No MaterialTheme default — Material widgets get themed to look like our system, not the other way round.
  • Focus. Default Android focus traversal works on both targets (Rokid temple → DPAD, RayNeo via the Mercury FocusHolder path bridged by TempleFocusBridge). Apply Modifier.r08Focus() for the universal 2 px left bar + 7 % accent tint indicator.
  • HUD. Implemented as a Compose composable hosted by an overlay WindowManager view in the foreground service (HaloRingService) — so it can appear above any app, not just ours. Auto-hides after the per-variant duration. Binocular re-anchor: see §4 audit-pass note.
  • Switches. All ON/OFF rows use the shared HaloSwitch pill. Don't use raw Text("ON" / "OFF") — colour-only state is too easy to miss on the waveguide.
  • Toggling system gestures. Tap a row in System Gestures → modal opens → GesturePicker screen → select gesture → conflict-checked against other slots before commit.
  • Brightness. Inherit system; never override. Wearers expect the glasses' anti-light-leakage mode to apply uniformly.
  • Pixel discipline. If a UI element fits in less ink, prefer that. Every illuminated pixel costs display power. Avoid filled icons; line icons at 1.5 px stroke. 16 sp text floor for everything except MetricKey (RayNeo dev-guide alignment, audit-pass 2026-05-13s).
  • i18n. All strings via strings.xml; ZH translations in strings-zh.xml. Action friendly names route through actionFriendlyText() — single source of truth shared with the gesture-hint HUD, Test Arena, and Action Picker.
