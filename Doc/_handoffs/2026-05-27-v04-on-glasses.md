## 2. What shipped in v0.4 (code)

### 2.1 Deletions (the phone-style-app cruft)
- `InAppFocusController.kt`, `TempleFocusBridge.kt`, `TabBar.kt`, `GuidedTour.kt`,
  `RayNeoTempleFocusBridge.kt` — **deleted**. The 3-tab top strip is gone; Compose's standard
  `FocusManager` + system KeyEvents handle navigation.
- 5-step FirstRunWizard → focused setup wizard (§2.4).

### 2.2 New input architecture
- **`SystemKeyDispatcher` (`:core`)** — base gestures → KeyEvent ints. `forBaseGesture()` returns
  a **List** now (a swipe dispatches BOTH axes — see §3).
- **`ActivitySystemKeyDispatcher` (`:app`)** — dispatches into the foreground Activity window.
- **`CompositeSystemKeyDispatcher` (`:app`)** — foreground → Activity window; **backgrounded →
  agent `injectKey` (system-wide)**. This is what lets the ring drive *other* apps.
- **`RokidTempleBroadcastReceiver` (`:app`)** — registers Rokid temple system broadcasts
  (`ACTION_SPRITE_BUTTON_*` / `ACTION_TWO_FINGER_*`) on the Service (C2). Rokid-flavor only.
- **`GestureSounds` (`:app`)** — distinct ToneGenerator tone per gesture (eyes-off feedback).

### 2.3 Gesture model (heavily iterated on glasses — see §3)
- **Base 4** (TAP/DOUBLE_TAP/SWIPE_UP/SWIPE_DOWN) hard-locked to system KeyEvents:
  - TAP → DPAD_CENTER, DOUBLE_TAP → BACK
  - **SWIPE dispatches BOTH a vertical + horizontal key** (SWIPE_UP → DPAD_UP + DPAD_LEFT;
    SWIPE_DOWN → DPAD_DOWN + DPAD_RIGHT) so it navigates vertical lists AND the horizontal
    Sprite Launcher app list.
- **LONG_PRESS = screen toggle** — system `wake` (screen off) AND `sleep` (screen on) both bound
  to LONG_PRESS. `longPressFollowupWindowMs = 60` (near-instant; firmware ~600 ms hold is the
  floor). This shadows per-profile LONG_PRESS while screen-on.
- **Combos retuned** — `comboWindowMs 300→400`, `multiTapWindowMs 280→300`. DOUBLE_TAP_SWIPE
  combos now trainable (user-confirmed). LONG_PRESS combos are effectively off at the 60 ms window.
- **WRIST_SHAKE** — NEW `Gesture`. `AccelProcessor.WristShake` (already detected, was log-only)
  now routes through `InteractionRouter.onGesture()` like a ring gesture. Default-bound to
  **OpenAIAssistant** (Nav/Media) / **OpenChat** (Reader). **Needs the accel stream ON** (Settings
  → Vitals → Spatial features, default OFF for battery).
- **Fast profile dropped** — Navigation / Media / Reader remain (Fast was redundant post-v0.4).

### 2.4 Setup wizard (mandatory, on-device, no computer)
3 steps, strict sequential single-button gating, **no Skip**:
1. **System access** — gates: dev-options OFF → "Enable Developer Options" (jumps to Build
   number; auto-enables via WRITE_SECURE_SETTINGS if held); wireless-debug OFF → "Open Wireless
   Debugging"; both ON → "Start pairing" (6-digit code via `AdbPairingOverlay`). **Agent-already-
   running detection** → "✓ done, continue" (no re-pair).
2. **Keep-alive** — battery exemption (auto-detected ✓) + auto-start (App info → Battery
   unrestricted; boot-restart is automatic via BootReceiver).
3. **Pair ring** — `RingPairingScreen`.
- **Battery exemption auto-requested** once on first launch.
- **Auto-recovery**: on startup, if setup was done but the agent isn't alive after a 7 s grace
  window, the wizard auto-re-enters (user ask).

### 2.5 Settings IA + Vitals
- Settings reorganised into 5 groups (Ring / Vitals / Gestures / Plugins / More); single-member
  groups (Ring, Plugins) navigate straight to their leaf (no "Ring → Ring").
- Capability-gated UI (Vitals hides Stress if no `hrv`; RingScreen shows capabilities list).
- Sport session UI (Walk/Run/Cycle, now a **vertical** stack) + SportTick HUD pip.
- Skip-wizard-if-paired guard (no re-pair every reinstall).

### 2.6 Energy fixes (from the audit, see §4)
- **Re-scan backoff** — auto-reconnect backs off 800 ms→30 s (resets on READY) instead of a
  back-to-back LOW_LATENCY scan loop.
- **Accel stream gated** on spatial-pref AND worn AND screen-on (`reconcileAccelStream()`).
- **Fast connect** — `connectGatt(autoConnect=false)` → ~2.7 s (was ~57 s).

### 2.7 Font / HUD
- Global `HaloType` scaled ×0.7 for the Rokid 480×640 panel (Title 24→17, Body 17→12, …).
- HUD pill fonts 11/10 sp; HUD fully `removeView()`s on hide (no residual ghost); 32 px safe
  margin (no edge clip); SportTick / RingDropped HUD variants added.
- Cta tracks Compose focus (`onFocusChanged`) → focused button fills solid green (the cursor was
  invisible before).

## 3. On-glasses findings (the stuff you can only learn on real hardware)

These reshaped the design — **do not regress them**:

1. **Rokid temple click fires `KEYCODE_ENTER` (66), NOT `DPAD_CENTER`** as the bare-metal doc
   claimed. Compose's `clickable` handles ENTER, so clicks work — but the doc's keycode table is
   from an older SDK.
2. **The Sprite Launcher app list is HORIZONTAL** (DPAD_LEFT/RIGHT); home / notifications /
   in-app are vertical (DPAD_UP/DOWN). → ring swipe must dispatch BOTH axes (§2.3). This was the
   "在 APP 列表里不能滑动" bug.
3. **No initial focus = frozen UI.** Deleting the TabBar removed the thing that grabbed initial
   focus; nothing was selected so clicks/swipes had no target. Fix: `FocusRequester` + `focusGroup()`
   in HaloRingApp / wizard / pairing screen.
4. **Long-press lag is firmware-bound.** Cutting our follow-up window 400→60 ms helped, but the
   ring's ~600 ms hold-to-register is in the R08 chip — unchangeable by any app/ADB.
5. **Combos were untrainable at a tight window** — widening comboWindow to 400 ms made
   DOUBLE_TAP_SWIPE trainable. (LONG_PRESS combos sacrificed for fast long-press.)
6. **Agent works on real Rokid** — `[halo.agent] resolved legacy InputManager (Android 12)` +
   `listening on abstract:halo.agent (uid=2000)`. `pm grant WRITE_SECURE_SETTINGS` succeeds on
   Rokid (OnePlus/Xiaomi strip it; Rokid doesn't).
7. **App-details has no "auto-start" toggle on stock AOSP** — that's an OEM (MIUI/EMUI) thing.
   Boot-restart is handled by `BootReceiver` + battery-unrestricted. Wizard text reworded.
8. **App can't focus a row inside system Settings** — cross-app focus control is blocked. We can
   only deep-link to a screen.

## 4. ⚠️ Critical caveats for the next agent

1. **The agent on the test Rokid was bootstrapped via USB, NOT the wireless pairing flow.** So:
   - It will **NOT survive a reboot** (USB-spawned process dies; no persisted wireless trust).
   - True reboot-survival needs the **wizard's wireless pairing run once** (establishes the
     persisted keypair + adbd `adb_keys` trust that `bootRecoverAgent` relies on).
   - **The wireless pairing flow (`AdbPairingOverlay` + mDNS + SPAKE2) has NEVER been validated on
     real Rokid hardware** — only on OnePlus loopback. This is the #1 thing to verify next.
2. **WRITE_SECURE_SETTINGS for a normal user comes from the agent** (`grantWriteSecureSettings()`
   runs `pm grant` over the wireless-ADB shell). The ONE unavoidable manual step is enabling
   Developer Options + Wireless Debugging once (Android security; even ADB can't bypass the
   build-number ×7).
3. **DOUBLE_LONG_PRESS → AI assistant is effectively dead** (the 60 ms follow-up window < the
   ~600 ms firmware hold, so a 2nd long-press can never land in-window). WRIST_SHAKE → AI
   assistant is the working trigger instead. The `aiAssistant = DOUBLE_LONG_PRESS` system slot
   default is now vestigial — consider rebinding it.
4. **Profile LONG_PRESS bindings are shadowed** by the system sleep gesture while screen-on
   (Media's `LONG_PRESS→MediaNext`, Reader's `LONG_PRESS→BrightnessUp` won't fire). Acceptable
   per the user's screen-toggle priority, but the Profile Editor still *shows* those dead bindings
   — a cosmetic cleanup opportunity.
5. **Energy audit (full report in the commit / agent transcript)** flagged two now-fixed issues
   (re-scan backoff, accel gating). Remaining minor: the out-of-app dual-keycode inject launches
   two separate coroutines → could batch under one agent lock for ordering (low priority).

   (PALM_UP/DOWN, POINT_*) + impact; only WRIST_SHAKE is wired so far. The user explicitly wants
   more sensor gestures ("根据手掌朝向来判断", flick/tilt). Add them as bindable `Gesture`s the same

   (vitals hero + ring status + MEASURE NOW), NOT the cold menu list it is now. Reference the old

   group bypass; the dashboard landing is the remaining piece).
