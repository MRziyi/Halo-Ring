## 1. What shipped this round (beyond the original v0.4 plan)

The v0.4 plan (Doc/20 §11 C1-C7) is fully implemented. The on-glasses burn-in then produced these
deltas (all in Doc/20 §17, summarised here):

- **Dual-axis swipe** — ring `SWIPE_UP → [DPAD_UP, DPAD_LEFT]`, `SWIPE_DOWN → [DPAD_DOWN, DPAD_RIGHT]`.
  Fixes navigating the **horizontal Sprite app list** (was vertical-only). `TAP → DPAD_CENTER`
  (Rokid temple click is actually `KEYCODE_ENTER`, Compose handles both), `DOUBLE_TAP → BACK`.
- **LONG_PRESS = screen toggle** — `SystemGestures.sleep` is now `LONG_PRESS`, so it wakes
  (screen-off) and sleeps (screen-on). Window cut to **60 ms** (near-instant; the ~600 ms
  firmware hold is the hard floor). Shadows per-profile LONG_PRESS while screen-on.
- **`WRIST_SHAKE` air-gesture** — new `Gesture.WRIST_SHAKE`, routed from `AccelProcessor` →
  `InteractionRouter.onGesture`, bindable, default → AI assistant (Nav/Media) / AI chat (Reader).
  Needs the accel stream (Settings → Vitals → Spatial features; gated worn + screen-on).
- **Per-gesture sounds** (`GestureSounds`) — distinct ToneGenerator tone per gesture.
- **Combo windows retuned** — `multiTapWindowMs 280→300`, `comboWindowMs 300→400` (trainability).
- **Fast profile dropped** — `DefaultProfiles.ALL = [Navigation, Media, Reader]`.
- **Energy** — BLE auto-reconnect exponential backoff (800 ms→30 s, resets on READY);
  `connectGatt(autoConnect=false)` (57 s→3 s connect); accel stream gated worn + screen-on.
- **`CompositeSystemKeyDispatcher`** — foreground → Activity window, background → agent (system-wide).
- **`RokidTempleBroadcastReceiver`** — temple system broadcasts → router (Rokid-flavor only).
- **Wizard reworked** — strict single-button sequential gate (dev-options → wireless-debug → pair),
  no Skip, agent-already-running detection, auto-enter on lost-perms at startup, jump-to-Build-number
  + auto-enable dev-options/wireless-debug when `WRITE_SECURE_SETTINGS` held, keep-alive step.

## 4. TOP open item (do this first)

**Wireless pairing + reboot-survival on Rokid.** The agent currently runs because it was
**USB-bootstrapped** (a dev shortcut to prove it works). For the real no-computer story:

1. Run the wizard's **wireless `AdbPairingOverlay` 6-digit flow** on the glasses (enable wireless
   debugging → START PAIRING → enter code). This is the one bootstrap step **never validated on
   Rokid** (only OnePlus loopback).
2. Confirm `WRITE_SECURE_SETTINGS` gets granted (it does on Rokid — `pm grant` returns 0).
3. **Reboot the glasses** and confirm `bootRecoverAgent` revives the agent with zero user action.
   Reboot-survival needs the wireless trust (persisted keypair + adbd `adb_keys`), which only the
   wireless flow establishes — the USB bootstrap does NOT set it up.

Until this is validated, don't claim "no computer + survives reboot" as done.
