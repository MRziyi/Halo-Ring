## 1. What shipped this round (v1.1.0)

### 1.1 Crash fix (was real, recurring)
- **Language-switch crash** — `HaloRingApplication.applyLanguage` ran the locale change (→
  `AppCompatDelegate.setApplicationLocales` → `Activity.recreate()`) on `Dispatchers.IO`, throwing
  `IllegalStateException: Must be called from main thread`. Now hops to `Dispatchers.Main`. Verified
  in `dumpsys activity exit-info` / dropbox as reason=4 APP_CRASH before the fix.

### 1.2 Gesture latency — measured + tuned (on-glasses, HaloLat probe)
Real end-to-end per-gesture decomposition (HIGH band): the **dispatch tail was ~30 ms** because the
gesture-hint HUD + sound ran **synchronously before** the action dispatched.
- **HUD + sound moved to a `serviceScope.launch{}`** in `onGestureRecognized` → dispatch **30 ms → 1–2 ms**.
- **`multiTapWindowMs` 300 → 220 ms** (200 was tried but made the 2nd tap of a double-tap too tight
  — Zack; reverted to 220). `longPressFollowupWindowMs` 60 → 40 ms (Nav/Media).
- Net measured: **SWIPE ~36 → ~5 ms**, **TAP ~320 → ~225 ms**, **LONG_PRESS ~85 → ~47 ms**.
- The single dominant latency is now the deliberate multi-tap/combo **disambiguation window** (TAP
  ~220 ms, DOUBLE_TAP ~400 ms `comboWindowMs`) — by design, not lag.

### 1.3 Conn-interval display was lying — removed
- The home RING-tab "NN ms" used `ConnIntervalEstimator`, which on this firmware (event-driven, not
  periodic notifies) mostly measured the **gap between the wearer's gestures** → showed 185–1330 ms
  for what is really a 15–500 ms link. **Removed the home display**; the estimator gained a 600 ms
  ceiling filter so it can't surface idle-gap garbage anywhere.

### 1.4 Ring-energy settings (new, wearer-tunable) — SPEC v3 §4.4 / §4.10
On-device verification first established the ring side is already well-managed (3-band BLE interval,
touch-IC off when not worn, 5-min not-worn disconnect, ~0.4 % idle app CPU, no reconnect churn).
The two discretionary drains are now user-controlled:
- **Touch-IC sleep timeout** (`sleepMin`, SPEC §4.10) — how long the touch sensor stays awake after
  the **last touch** before sleeping. Was a hardcoded 10 min; now **Settings → Power & Connection →
  Ring sleep**, presets 1/2/5/10/15/30 min, **default 5**. Plumbed: `R08Protocol.touchModeCmd(sleepMin)`
  + `setTouchEnabled(enabled, sleepMin)` with a `lastTouchSleepMinRequested` idempotence tracker;
  stored in `AdvancedPrefs.touchSleepMin`; service mirrors it and re-applies via `reconcilePower()`.
- **Vitals auto-detection** (replaces the ring's HR-only `0x16`) — app-driven **HR + SpO₂** group on
  a schedule. **Settings → Vitals → Auto-detect** (toggle, **default ON**) + **Detection interval**
  (15/30/60/120/240 min, **default 60**). The ring's autonomous `0x16` HR-auto is now **always
  disabled** (`setHrAutoMonitor(false)`) so it doesn't double-measure.

### 1.5 Cold-launch home focus lockup — fixed
- On the **first** (cold) home entry the focusable content (RECONNECT/FIND) sometimes hadn't been
  placed within the old 1.44 s `requestFocus` retry budget, so the cursor never landed — and with no
  focus owner the swipe DPAD events never reached the tab-overflow handler, so up/down did nothing
  and the wearer had to exit + re-enter. Retry budget raised to ~9.6 s (warm entries still land on
  the first try and return immediately). [`HaloRingApp.kt`]

### 1.6 Other
- Removed a per-event `Log.i("raw gesture")` (fired ~33×/s during a swipe burst).
- Reverted the v0.7-era "override gestureConfig from DefaultProfiles by id" in `ProfilesPrefsStore`
  — it silently reverted the wearer's **Power & Connection** timing edits on every restart. Now the
  persisted config is respected; `MULTI_TAP_PRESETS` gained 200.

## 4. Don't-undo list

- **HUD + sound are async** in `onGestureRecognized` (action injects first). `cancelHudAutoSleep()`
  stays synchronous.
- **`multiTapWindowMs = 220`** — 200 was too tight for double-tap (Zack).
- **Ring `0x16` HR-auto stays disabled** — vitals auto-detection (HR+SpO₂) replaces it; don't
  re-enable both or the ring double-measures.
- **Bootstrap TOUCH_MODE is null-guarded** — don't make it unconditionally write the default sleepMin
  (it would clobber the wearer's setting until the next reconcile).
- **Home focus retry budget is large on purpose** (cold-launch composition jank). Warm entries
  return on the first try.
- **No home "conn interval ms"** — the estimator can't measure it on this firmware.
