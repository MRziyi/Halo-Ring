## 1. Gesture + interaction changes (all on-device-driven)

- **Long-press follow-up window** 60 → **30 ms** (`GestureConfig.longPressFollowupWindowMs`). The
  firmware ~0.6 s hold is the floor; this is the only app-side lever. LP-combos are effectively off.
- **Gesture sounds rewritten** ([`GestureSounds`](../app-project/app/src/main/kotlin/com/halo/ring/ui/GestureSounds.kt)):
  ToneGenerator DTMF → synthesised sine blips on a C-pentatonic ladder (pleasant + distinct).
- **WRIST_SHAKE dropped** (still in the `Gesture` enum + `AccelProcessor` detects it, but unrouted +
  hidden from the picker). Root cause: the firmware shake (`0x73 sub=0x29`, needs `appType=7`) is
  **mutually exclusive** with the touch gestures (`appType=9`) on RT08 — confirmed via SPEC v3 +
  Zack's on-device test. Only the `0xA1` accel stream could coexist (energy cost) — deferred.
- **New `TAP_SWIPE_UP` / `TAP_SWIPE_DOWN`** (single-tap-then-swipe) in [`GestureSynthesizer`](../app-project/core/src/main/kotlin/com/halo/ring/core/gesture/GestureSynthesizer.kt).
  Easier than double-tap-swipe; took over the primary combo actions. `DOUBLE_TAP_SWIPE_*` is now
  **free for user-custom** (None default). Forms only when `awaitCombos && !optimisticSingleTap`.
- **TRIPLE_TAP = system Screenshot** (shared via `systemSlots`, all profiles). **QUADRUPLE_TAP
  disabled** (`enableQuadrupleTap=false`, hidden).
- **Screen wake = DOUBLE_TAP when screen-off** (was LONG_PRESS); **LONG_PRESS = screen-sleep only in
  the Navigation/fallback profile** (`ModeManager.isFallbackActive()` gates it). App profiles own
  LONG_PRESS for themselves.
- **Profiles auto-only**: no manual switching (ProfileCycle gesture + picker entry removed). The
  active profile is inferred purely from the foreground app.
- **Default profiles** (`DefaultProfiles.ALL = [Navigation, Media, Reader]`, Camera dropped):
  - Navigation (fallback): base nav; LONG_PRESS=sleep; TAP_SWIPE_UP=**Subtitle**, TAP_SWIPE_DOWN=AI.
  - Media (`useSystemKeyEvents=false` so base gestures route through the map): TAP=play/pause,
    DOUBLE_TAP=exit, swipes=volume, TAP_SWIPE_UP/DOWN=prev/next track.
  - Reader: page-nav swipes; LONG_PRESS=brightness; TAP_SWIPE_UP=Subtitle, DOWN=Translate.
  - **DOUBLE_TAP = exit in every profile** (Zack's invariant).
- **New action `OpenSubtitle`** → Rokid Sprite live-caption `AccessibilityPageActivity` (verified it
  launches + **stays**, unlike the Sprite camera which bounces).

### The big bug fixed this session
Profiles auto-switch by **foreground ACTIVITY class**, not just package — every Sprite "app"
(camera/music/translate/caption) is the **same package** `com.rokid.os.sprite.launcher` with a
distinct activity, so package-only matching never fired (`HaloRingAccessibilityService` now forwards
`event.className` + filters to real `*Activity` transitions + **ignores our own package**). Without
the own-package filter, showing the ProfileSwitched HUD re-fired a window-state event that reverted
the profile to Navigation ~150 ms after every switch — which is why "music tap did nothing / camera
long-press slept": the ring was stuck in Navigation. Fixed + validated (Media/Camera stay).

### HUD
- **Root-caused why no HUD ever showed**: `SYSTEM_ALERT_WINDOW` wasn't granted → overlay never
  created → every `hud?.show()` was a silent no-op. The agent now grants it via
  `AdbBootstrap.grantOverlayPermission()` (`appops set … SYSTEM_ALERT_WINDOW allow`) at bootstrap.
- ProfileSwitched HUD redesigned: per-profile content icon (🧭/🎵/📖), no legacy "cycle" wording.

### Ring power
- **No LED blink on profile switch by default** (`ringLedFeedback=false`); switches are frequent now.
- **Touch-IC sleep timeout** `TOUCH_MODE` sleepMin 1 → **10 min** (fewer dozes). Trade-off: touch IC
  awake longer = a bit more battery; tune the 4th byte of `R08Protocol.TOUCH_MODE` if needed.

## 2. Plugin exclusive-overlay (the headline new capability)

Doc/18 §5 (the "§7 model") — see [Doc/18](../18-plugin-protocol.md) §5 for the wire protocol and
[`Constellation/docs/cross-device/RESP-halo-ring-overlay-protocol-v1.md`](../../Constellation/docs/cross-device/RESP-halo-ring-overlay-protocol-v1.md)
for the interface note sent to the plugin.

**Design (Zack-approved over Constellation's own REQ):** the overlay is an **exclusive profile**, not
a per-gesture binding-stack. While a plugin's HUD is up it owns the **whole** ring; Halo Ring
forwards **raw gesture names** to the plugin and leaks nothing to the underlying app; the **plugin
owns all semantics + on-HUD prompts** (so it can remap meaning per HUD-state with no round-trip).

**Implementation:**
- [`OverlayController`](../app-project/core/src/main/kotlin/com/halo/ring/core/plugin/OverlayController.kt)
  (core, pure-JVM, unit-tested) — single-active state + 60 s keepalive timeout. **Replaced
  `ProfileStack` + `PluginBindingsParser`** (deleted).
- [`InteractionRouter`](../app-project/core/src/main/kotlin/com/halo/ring/core/gesture/InteractionRouter.kt)
  §0a: if `overlayCaptures()` → `forwardOverlayGesture(gesture)` + consume (highest priority after
  the screen-off wake path). The old `pushedProfileLookup` layer is gone.
- [`PluginBroadcastReceiver`](../app-project/app/src/main/kotlin/com/halo/ring/plugin/PluginBroadcastReceiver.kt):
  `OVERLAY_ACTIVATE` / `OVERLAY_DEACTIVATE` in (gated by `PUSH_PROFILE` signature perm); legacy
  `PROFILE_PUSH/POP` aliased. [`HaloRingService`](../app-project/app/src/main/kotlin/com/halo/ring/service/HaloRingService.kt)
  forwards `OVERLAY_GESTURE` out to the owner, freezes profile inference while active, shows the
  activation HUD, and releases on uninstall / keepalive-timeout.

**NOT yet validated end-to-end** — this is the TOP open item (§4).

## 5. Gotchas / invariants for the next agent

- **SPEC v3.md is the only protocol ground truth** for the ring — never conclude from decompiled
  `refs/`. (Burned an hour on this; Zack corrected it.)
- **`useSystemKeyEvents=false`** is the lever that makes a profile's base gestures (TAP/swipes) route
  through its map instead of the hard-locked DPAD passthrough. Media + the overlay both rely on it.
- **DOUBLE_TAP=exit everywhere; TRIPLE_TAP=screenshot; LONG_PRESS=sleep only in Navigation.** Don't
  regress these without Zack's say-so.
- **Profile inference must ignore our own package + only react to real `*Activity` windows** — or the
  HUD re-fires a revert loop.
- The router layer order now: screen-off wake → **overlay capture** → system sleep (fallback only) →
  system slots → modal → base-key passthrough → profile.
- Reports to Zack in **中文**; fast on-device iteration; "just do it + I'll test".
