## 1. What shipped this round (v0.7.0)

### 1.1 The 3-tab home (the headline)
Root is now [`HomeDashboardScreen`](../../app-project/app/src/main/kotlin/com/halo/ring/ui/screens/HomeDashboardScreen.kt):
a horizontal **RING · VITALS · MORE** strip sized for the Rokid **480×640 portrait** panel.
- **Tab switching is the in-app `LONG_PRESS` context gesture** (InteractionRouter §0b): when our
  Config Activity is foreground, LONG_PRESS cycles tabs; out-of-app it still sleeps the screen.
  The tab strip is a **non-focusable indicator** — swipe focus stays purely on the active tab's
  content (Zack: "focus should never land on a tab"). Wiring: router `appForeground` /
  `onAppTabCycle` hooks → `AppGraph.homeTabIndexFlow` (single source of truth) → MainActivity
  collects → `homeTab` param.
- **RING tab** (default, most-used): name + live status (`connected · battery · interval`) +
  RECONNECT / FIND RING + drill-ins **Ring info** / **Power & Connection**.
- **VITALS tab**: compact HR + SpO₂ readout + measured-ago + MEASURE + a "Vitals settings" drill-in.
- **MORE tab**: a flat list — **Profiles & Gestures, Feedback, Bluetooth Internet, Language,
  Advanced, About**.

### 1.2 IA reorg (each tab owns its settings)
- Ring + Power settings → RING tab drill-ins. Vitals settings → VITALS tab drill-in.
- **System Gestures + Test Arena moved INTO the Profiles screen**, placed *below* Restore-defaults
  under a "Gesture tools" header (they're gesture-config extras, not the headline).
- **External Plugins + Open Android Settings moved into Advanced.** **Latency toggle + all CSV
  exports removed** (use debug tools). The old **Connection Status** screen is gone (unreachable);
  its one useful field, the **BLE connection interval**, is on the RING tab's first line.
- "Ring" drill row renamed **"Ring info"** (戒指信息) to avoid two "Ring"s. Ring-info de-duped to
  the detail-only fields: MAC / firmware / signal / capability chips / Pair / Forget.

### 1.3 Protocol-backed UX (all from SPEC v3 verified opcodes)
- **Charging milestones** — `0x73` sub-0C push (already decoded) → `RingInfo.charging`; status-bar
  green-% + RING-tab "Charging · N%"; HUD at dock-in / 90 / 95 / full (each once per session,
  debounced vs the ~60 s heartbeat). Low-battery suppressed while charging.
- **Every-500-steps HUD** — passive `0x73` sub-12 step stream; HUD at each 500 boundary (no goal).
- **Wear sensing** — `0x2A` touch-status + the wear pipeline → `RingInfo.worn`; wear-change HUD,
  RING-tab "not worn", MEASURE shows "Put the ring on" instead of grinding to wear-fail, and an
  **auto-snapshot on the worn-transition** ("戴上即测") so the readout is fresh without a manual tap.
- **Live RSSI** — `readRemoteRssi` polled ~1/s in the service ring-info refresh. **This fixed a real
  bug**: `RingInfo.rssiDbm` was *never* set for the connected ring (only scan-time, for the pairing
  picker), so the signal always showed "—".
- **Drop / Reconnected HUDs** — were already wired; confirmed.

### 1.4 HUD polish
- **`showAlert()`** in `HaloRingService`: alert-class HUDs (charging / step / wear / drop /
  low-battery / (dis)connect) **wake a sleeping screen, show, then auto-sleep after ~7 s**
  (`HUD_AUTO_SLEEP_MS`); a recognised gesture cancels the pending sleep. Frequent HUDs
  (gesture-hint / profile / sport tick) bypass it (they'd wake the screen constantly).
- **User HUD vertical offset** — `FeedbackPrefs.hudOffsetSteps` (0–5 body units, ~one pill-height
  each). Top-anchored positions move DOWN, bottom-anchored move UP (so the HUD clears a plugin's own
  HUD, e.g. Constellation). Default 2. Feedback → "HUD offset" cycles it.
- **4 corner positions** — `HudPosition` gained TopLeft / BottomLeft (now TL/TR/BL/BR + TopCenter).

### 1.5 Vitals truthing + placeholder removal
- Vitals show **only HR + SpO₂** — the two metrics RT08_3.10.46 actually computes. HRV/Stress, BP,
  temperature are advertised by the capability bitmap but `val` stays 0 (SPEC §10.5), so they're
  gone. MEASURE fires HR (`0x69[01,01]`) + SpO₂ (`0x69[03,01]`) **in parallel** — one tap, both.
- Removed the **AI-dictate** picker entry (mic pipeline unimplemented) — **no "(coming soon)"
  reachable on the Rokid daily path**.

### 1.6 Bug fixes this round
- **RING first-launch had no focus** (cold-frame race; a single `requestFocus` silently no-op'd).
  Now retries **until focus is confirmed landed** (verified via `onFocusChanged.hasFocus`, ~1.4 s),
  then stops (doesn't re-yank). Re-anchors on tab change too.
- **Feedback showed two cursors** — a fixed `focusedIndex==0` highlight stacked on the Compose
  focus highlight. Removed `focusedIndex` entirely; Compose focus only (matches every other screen).
- **Double divider** in Ring-info (signal↔capabilities) and About (device↔source) — a `ListRow`
  already draws a trailing divider; an explicit one after it made a second line. Removed the extras.
- **Cta buttons too big** — vertical padding 12→8 dp, font 16→14 sp (global).
- **Capabilities cut off** — rendered as a wrapped **FlowRow of chips**, and moved *above* the
  Pair/Forget buttons so the focusable buttons stay last (focus-scroll can't reach content that
  trails the last focusable).

## 4. Don't-undo list (each was a deliberate fix)

- **Non-focusable tab strip + LONG_PRESS tab switch.** The dual-axis focus-juggling for a focusable
  horizontal strip was "too confusing" (Zack). Tabs are indicators; focus lives in content.
- **RING first-launch focus = retry-until-`hasFocus`.** A single requestFocus races the first frame.
- **Live RSSI via `readRemoteRssi`** in the refresh loop. Scan-time RSSI never reached `ringInfoFlow`.
- **`showAlert()` wake-and-auto-sleep** wraps alert-class HUDs only (NOT gesture-hint/profile/sport).
- **Vitals = HR + SpO₂ only** — HRV/BP/temp never compute on this firmware (SPEC §10.5).
- **ListRows own their trailing dividers** — never add an explicit `Box(divider)` right after one.
- **Each tab owns its settings**; MORE is the flat misc list with rare bits inside Advanced.
- **Home renders OUTSIDE the verticalScroll** (HaloRingApp) — a scroll container between the focus
  group and the content stole the initial focus. Sub-screens keep their own scroll.

## 5. Gotchas / invariants

- **SPEC v3.md is the only protocol ground truth** — never conclude from decompiled `refs/`.
- `useSystemKeyEvents=false` routes a profile's base gestures through its map (Media + overlay rely
  on it). DOUBLE_TAP=exit everywhere; TRIPLE_TAP=screenshot; LONG_PRESS=sleep only out-of-app
  (in-app = tab switch).
- Profile inference must ignore our own package + only react to real `*Activity` windows.
- `AppGraph.homeTabIndexFlow` is the single source of truth for the active tab (UI reads it; the
  LONG_PRESS gesture writes it via the service).
- Charging-milestone tracker (`wasCharging` / `lastChargeMilestone`) resets on unplug; step
  milestone (`lastStepMilestone`) resets on a counter rollback (new day).
- Force-stopping the app **disables the accessibility service** — re-enable after testing (see §6).
