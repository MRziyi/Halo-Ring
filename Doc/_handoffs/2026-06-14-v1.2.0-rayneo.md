# Handoff — 2026-06-14, v1.2.0 (RayNeo X3 Pro brought up on real hardware)

> Point-in-time snapshot. Builds on [`2026-06-01-v1.1.6-shipped.md`](2026-06-01-v1.1.6-shipped.md).
> `versionName 1.2.0` / `versionCode 21`. Everything here is **RayNeo-flavor only — Rokid is byte
> unaffected** (verified: rokid debug builds + `:core` tests green, no behavioural change).

First session on the real **RayNeo X3 Pro (ARGF20 / MercuryLiteXR / AIOS Android 12)**. RayNeo turned
out to be a much harder target than Rokid; this version makes the ring-remote actually work on it.

## 1. What we learned on-device (RayNeo ≠ Rokid)
- **Input model**: temple touchpad → raw MotionEvents → each app's Mercury SDK `TouchDispatcher` →
  `TempleAction` (per-app, NOT global KeyEvents like Rokid). Verified: an injected **touchscreen
  swipe drives Mercury nav** (SlideForward/Backward), a **tap = Click**, double-tap / `KEYCODE_BACK`
  = back. **DPAD keys do nothing** on Mercury apps. Display = 1280×480 binocular (left 640 → left
  eye, right 640 → right eye). Injection uses **display** coords, not touchpad coords.
- **The agent can't bootstrap**: AIOS SELinux blocks the v0.5 transport (`setprop
  service.adb.tcp.port` / `persist.adb.tcp.port` / `ctl.restart adbd` all denied for shell;
  `adb_wifi_enabled` won't stick; `adb_keys` unreadable). So no self-provisioned ADB agent.
- **Launcher force-stops backgrounded apps**: `com.ffalconxr.mercury.launcher` (holds
  `FORCE_STOP_PACKAGES`) runs `BackgroundAppManager` that `forceStopPackage`s any non-whitelisted
  third-party app ~2 s after it leaves the foreground (kills FGS + a11y). Decompiled the launcher:
  the abort condition is `inWhiteList(pkg) && paired`, `WHITE_LIST` is a hardcoded ~45-entry list.

## 2. What shipped (all RayNeo-gated)
- **Injection via accessibility** (no agent): `AccessibilityBackend(mapper, gesturesEnabled=true)`
  (rayneo bindings only) realises Tap/Swipe via `dispatchGesture` + global Back/Home/Recents via
  `performGlobalAction`. Needed `canPerformGestures="true"` — shipped as a **rayneo res override**
  `app/src/rayneo/res/xml/halo_ring_accessibility_config.xml` (base/rokid stay `false`).
  `dispatchGesture` must be posted to the **main thread** (off-main → callback never fires).
- **Background survival**: rayneo `applicationId = "com.mudra.mudraband"` — a whitelisted (Mudra
  gesture-wristband, same input-peripheral category) + on-device-absent package id, so the launcher
  exempts us. Requires the glasses paired to a phone (`&& paired`). Verified: `forceStopApp abort …
  inWhiteList`, survives backgrounding.
- **Wizard**: rayneo `SystemAccessStep` requires ONLY accessibility, skips Developer Options / Wi-Fi
  / Wireless Debugging / ADB pairing (the "老是要开发者权限" nag). Goes straight to ring pairing.
- **Binocular display**: HUD renders in **both eyes** (`BinocularHudPill`); the whole config UI is
  mirrored via `BinocularMirror` (record-once-with-a-GraphicsLayer, draw-twice) → one NavHost
  back-stack, interaction in the left copy, right eye is a per-frame pixel blit (no 2nd composition).
  Fixes the x=640 nose-seam split. Has a **stereo-depth hook** (opposing per-eye x-offset, 0 today).
- **Debug**: `com.halo.ring.TEST_ACTION` broadcast (rayneo debug only) dispatches a GlassAction by
  name through the router without the ring.

## 3. RayNeo isolation (no repo split)
Kept the product-flavor model. Device-specific code is only ~3.5% of the tree (638 LOC); `:core` is
100% shared. Isolation = `src/rayneo/` source sets + `src/rayneo/res/` overrides + a few
`BuildConfig.DEVICE_FLAVOR=="rayneo"` gates + a `gesturesEnabled` ctor flag. Revisit a split only if
shared screens fill with rokid/rayneo branches.
