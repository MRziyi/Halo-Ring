## 1. What shipped (v1.1.1)

### 1.1 Gesture audio — rebuilt on SoundPool
The per-gesture blip went through several fixes (all on-device with Zack):
- **Audible again** — the Rokid glasses mute every stream except **STREAM_MUSIC** (verified via
  `dumpsys audio`: NOTIFICATION / SYSTEM / ALARM / DTMF all `Muted:true`). The blip played on
  STREAM_NOTIFICATION → silent. Now routed to STREAM_MUSIC (`USAGE_MEDIA`).
- **No end "pop", no volume pumping, no lag-then-burst** — the old "new AudioTrack per blip" design
  cost ~100 ms to create+start (latency) and overlapped tracks on fast gestures (volume pumping /
  channel artefacts); a MODE_STREAM attempt buffered + burst. Final design = **SoundPool**: all 16
  blips pre-rendered to WAV + loaded once at `GestureSounds.init()`, so `play()` is a near-zero-latency
  in-memory trigger and SoundPool's mixer handles concurrency. A 45 ms rate-limit drops burst repeats.
- **Volume** is `GestureSounds.volume` (0..1), currently **0.16** (was too loud higher); tune live.
- `GestureSounds.init(applicationContext)` is called from `HaloRingService.onCreate`.

### 1.2 Gesture-combo settings (the headline)
The RING-tab drill-in **"功耗&连接" → "手势组合设置"** (Gesture combos). The old single `awaitCombos`
flag **wrongly gated BOTH** TAP_SWIPE (single-tap combo) and DOUBLE_TAP_SWIPE (double-tap combo), so
they couldn't be controlled separately. **Split into three independent groups**, each a switch + its
own window (per profile's `GestureConfig`):

| Group | Gestures | Switch | Window | Default |
|---|---|---|---|---|
| 单击组合 | TAP_SWIPE_UP/DOWN | `enableTapSwipe` | `multiTapWindowMs` (220) | **ON** |
| 双击组合 | DOUBLE_TAP_SWIPE_UP/DOWN | `enableDoubleTapSwipe` | `comboWindowMs` (**300**) | **OFF** |
| 长按组合 | LONG_PRESS_SWIPE_UP/DOWN + DOUBLE_LONG_PRESS | `awaitLongPressCombos` | `longPressFollowupWindowMs` (40) | **OFF** |

- **DOUBLE_TAP is never gated** — always recognised (= Back). It uses `multiTapWindowMs` only for
  DOUBLE-vs-TRIPLE disambiguation.
- **Triple-tap independence fix**: splitting the flag initially broke TRIPLE_TAP (a 2nd tap committed
  DOUBLE_TAP immediately when double-tap-swipe was off). The synth now holds the DOUBLE_TAP if EITHER
  a 双击组合 swipe OR a 3rd tap could still follow (`GestureSynthesizer` tapCount==2 branch).
- **Profile editor greys** the combo gestures whose group switch is off (mute + non-tappable + "在手势
  组合中开启" / "Enable in Gesture combos") — `ProfileEditorScreen.comboDisabled()`.
- **LONG_PRESS_SWIPE_UP → None** in every default profile (was Notifications / BrightnessDown).
- **Touch-sleep (Ring sleep)** moved from this screen to **Ring info** (`RingScreen`) — it's a
  ring-hardware power knob, not a combo setting.

### 1.3 HUD ↔ combo (verified)
A combo gesture bound to a non-None action fires the gesture-hint HUD (onGestureRecognized →
`gestureHintHud && action != None`). When its group switch is off the synth never emits it → no HUD.

## 3. Gotcha for an already-seeded device
Persisted profiles win over new code defaults (we respect user edits). A device seeded before v1.1.1
keeps its old `awaitLongPressCombos` (= true) — so **长按组合 shows ON until the wearer hits Profiles →
Restore default bindings** (or toggles it in 手势组合设置). `enableTapSwipe`/`enableDoubleTapSwipe`
are new keys → they take the new defaults (on / off) on any device.

## 4. Don't-undo list (additions)
- **Gesture audio = SoundPool on STREAM_MUSIC.** Don't go back to per-blip AudioTrack (latency +
  concurrency artefacts) or STREAM_NOTIFICATION (muted on the glasses).
- **Three independent combo switches.** Don't re-merge into one `awaitCombos`.
- **DOUBLE_TAP / TRIPLE_TAP never gated by a combo switch.**
- **LONG_PRESS_SWIPE_UP = None by default**; **comboWindowMs = 300**.
